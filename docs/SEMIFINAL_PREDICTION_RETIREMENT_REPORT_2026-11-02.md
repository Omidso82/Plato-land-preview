## ۱. هدف و دامنه قابلیت موقت

صفحه‌ای موقت برای دریافت پیش‌بینی اعضای PLATO LAND درباره برندگان دو مسابقه نیمه‌نهایی ساخته شد:

| مسابقه | بازیکن اول | Plato ID | بازیکن دوم | Plato ID |
|---|---|---|---|---|
| نیمه‌نهایی اول | رامش | `95m` | سعید | `_34EED` |
| نیمه‌نهایی دوم | هانا | `HANA1272` | لاوین | `LVIN` |

هر شرکت‌کننده باید برنده هر دو مسابقه را انتخاب می‌کرد و Plato ID خود را وارد می‌کرد. ثبت تکراری با شناسه نرمال‌شده جلوگیری می‌شد و پس از ثبت، امکان ویرایش رأی برای شرکت‌کننده وجود نداشت. آمار عمومی نمایش داده نمی‌شد؛ گزارش فقط در مسیر مالک قابل مشاهده بود.

متن اطلاع‌رسانی صفحه اعلام می‌کرد شرکت در پیش‌بینی مخصوص اعضای گروه PLATO LAND است و عضویت/فعالیت توسط Owner و مدیریت گروه بررسی می‌شود.

## ۳. ساختار داده و امنیت

جدول مستقل رأی‌های نیمه‌نهایی:
- `public.plato_land_semifinal_prediction_votes`
- ستون‌ها: `id`، `voter_plato_id`، `voter_plato_id_normalized` (generated)، `semifinal_one_winner_key`، `semifinal_two_winner_key`، `created_at`.
- برای شناسه نرمال‌شده قید یکتایی وجود داشت تا یک Plato ID بیش از یک بار رأی ندهد.
- RLS فعال بود و دسترسی مستقیم anon/authenticated به جدول لغو شده بود؛ مسیرهای Edge Function با service role عملیات لازم را انجام می‌دادند.
- Edge Function گزارش مالک، نشست Bearer و نقش مالک را بررسی می‌کرد.
- نام توابع:
  - `plato-land-semifinal-prediction-vote`
  - `plato-land-semifinal-prediction-owner-votes`

**مرزبندی تغییر نهایی:** در PR #38 هیچ migration، SQL، جدول، policy، رکورد، Edge Function، تنظیم Auth یا Storage تغییر نکرد. این PR فقط routing و فایل fallback مسیر عمومی را تغییر داد. تغییر قبلی HTTP 410 برای توقف رأی، مستقل از PR #38 و در مرحله قبل انجام شده بود.

جدول قدیمی `public.plato_land_prediction_votes` مربوط به پیش‌بینی قهرمان بود و **۱۸ رأی قبلی** داشت. آن جدول و آرای آن مستقل از پیش‌بینی نیمه‌نهایی است و نباید با جدول ۱۲ رأی نیمه‌نهایی ادغام یا جایگزین شود. پنل مالک پیش‌بینی قدیمی نیز در تغییرات این چرخه حذف نشده است.

## ۶. وضعیت Build، Deploy و تأیید زنده

- PR #38 در `main` ادغام شد.
- در بررسی اولیه Commit، ابزار GitHub فهرست workflow run مرتبط را خالی برگرداند؛ بنابراین از آن بررسی به‌تنهایی نمی‌شد اجرای Deploy خودکار را اثبات کرد.
- بررسی مستقل URLها در آن زمان با خطای cache miss روبه‌رو شد و تأیید زنده ممکن نبود.
- **پس از آن، مالک اعلام کرد سایت دوباره بالا آمده و صفحه اصلی نمایش داده می‌شود.** این تأیید مشاهده‌ای مالک است و در این گزارش به‌عنوان وضعیت فعلی ثبت می‌شود.
- این تأیید را نباید با گزارش یک CI یا تست خودکار مرورگر اشتباه گرفت؛ در PR #38 نتیجه Build/TypeScript یا workflow مستقل در این گزارش ادعا نمی‌شود.
