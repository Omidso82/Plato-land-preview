## 2. هدف و دامنه پروژه

PLATO LAND Tournament Platform؛ پلتفرم مسابقات با رابط فارسی RTL، طراحی مشکی و طلایی، اولویت موبایل و پشتیبانی از بازی‌ها و مسابقات. شعار: «بازی، رقابت، قهرمانی».

فناوری‌های ثبت‌شده:
- React + TypeScript + Vite
- Supabase: PostgreSQL، Auth، Storage و Edge Functions
- GitHub Pages برای Production
- Cloudflare Pages برای Preview

این بسته بر آخرین کار جاری متمرکز است: تکمیل طراحی Preview، سپس ایجاد Staging مستقل، آزمایش قابلیت‌های واقعی و انتشار کنترل‌شده به Production. سایر تصمیم‌های محصول و تاریخچه در اسناد پروژه و حافظه قابل دسترس باید بررسی شوند؛ این بسته جایگزین کل تاریخچه PLATO LAND نیست.

## 5. تصمیم‌های نهایی اخیر — Staging و انتشار

مالک گزارش کامل «فرآیند ایجاد محیط Staging و انتشار امن PLATO LAND» را تأیید کرده است. این تصمیم‌ها قطعی‌اند:

1. سه محیط مستقل از نظر کاربرد داریم: Preview برای طراحی، Staging برای آزمایش عملکرد واقعی، Production برای کاربران و داده‌های واقعی.
2. Staging هنوز ایجاد نشده است.
3. مبنای ساخت دیتابیس Staging، schema فعلی و تأییدشده دیتابیس اصلی است؛ شروع از صفر مطلوب نیست.
4. ابتدا ساختار دیتابیس اصلی بررسی می‌شود؛ سپس ساختار معتبر به پروژه Supabase مستقل Staging منتقل می‌شود.
5. اطلاعات خصوصی و واقعی کاربران، رمزها، sessionها، توکن‌ها، مدارک و سوابق شخصی Production به Staging منتقل نمی‌شوند.
6. داده‌های ساختگی و حساب‌های تست برای Owner، Manager و Player ایجاد می‌شوند.
7. Auth، Storage، RLS، Edge Functions، Secrets و سرویس‌های بیرونی باید جداگانه پیکربندی شوند.
8. جدایی اتصال Staging از Production باید پیش از تست با شواهد فنی اثبات شود.
9. دیتابیس آزمایشی هرگز جایگزین دیتابیس اصلی نمی‌شود.
10. تغییرات دیتابیس Production فقط از طریق Migrationهای کوچک، نسخه‌بندی‌شده، بازبینی و آزمایش‌شده انجام می‌شوند.
11. قبل از هر تغییر Production، backup و برنامه بازگشت بررسی می‌شود.
12. هیچ انتشار Production بدون گزارش تغییرات و تأیید صریح مالک انجام نمی‌شود.
13. هزینه یا ارتقای سرویس بدون بررسی و تأیید مالک ممنوع است.
14. هر آیتم چک‌لیست فقط پس از انجام واقعی، بررسی شواهد و تأیید مالک تیک می‌خورد.
