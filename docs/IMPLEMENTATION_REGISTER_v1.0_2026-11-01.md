## 4. پنل مدیر مسابقه — مجوزهای scoped
چهار مجوز مستقل برای هر مسابقه:
- `registrations`: درخواست‌ها و مدارک ثبت‌نام.
- `groups`: گروه‌بندی و قرعه‌کشی.
- `schedule`: برنامه و زمان‌بندی.
- `results`: نتایج و جدول.

پیاده‌سازی:
- جدول `public.tournament_manager_section_permissions` با RLS و کلید مرکب tournament/user/permission.
- تابع `private.can_manage_tournament_section(uuid,text)` برای اعمال مجوزها در RLS و عملیات مرتبط.
- `public.current_user_role()` نقش `tournament_admin` را از واگذاری مسابقه استنتاج می‌کند، نه از نقش مالک.
- حداکثر دو مدیر برای هر مسابقه در UI.
- ذخیره اتمیک از مسیر `public.save_tournament_manager_access(uuid,jsonb)` با SECURITY INVOKER؛ کنترل مالکیت و RLS فقط برای مالک.
- مدیران groups/schedule/results فقط داده شرکت‌کنندگان تأییدشده و غیرذخیره موردنیاز را می‌خوانند.
- مدارک خصوصی و pending فقط در محدوده registrations هستند.
- assignmentهای legacy با `permissions_configured=false` تا زمان بازبینی مالک رفتار قبلی را حفظ می‌کنند.
- تست SQL تراکنشی groups-only موفق و rollback شده؛ هیچ assignment آزمایشی در DB باقی نمانده است.
- تست E2E با حساب‌های واقعی هنوز انجام نشده است.
