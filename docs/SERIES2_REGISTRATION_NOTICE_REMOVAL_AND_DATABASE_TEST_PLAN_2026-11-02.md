## ۴. وضعیت اتصال ثبت‌نام به دیتابیس اصلی

کد فرم در `src/Series2Registration.tsx` درخواست POST را به Edge Function زیر می‌فرستد:

`plato-land-series2-registration`

پروژه Supabase اصلی: `dfrppbapaaydbjeflozw`

جدول مقصد که در دیتابیس اصلی بررسی شد:

`public.plato_land_series2_registration_requests`

ستون‌های موجود:
- `id` — شناسه UUID
- `plato_id` — شناسه Plato بازیکن
- `plato_id_normalized` — مقدار نرمال‌شده، nullable
- `rules_accepted` — پذیرش قوانین
- `created_at` — زمان ثبت با timezone

فرم پس از پاسخ موفق Edge Function پیام ارسال موفق و قرار گرفتن درخواست برای بررسی مدیریت را نمایش می‌دهد. این پیام به معنی تأیید نهایی بازیکن توسط مدیریت نیست.

## ۶. برنامه آزمون End-to-End

مالک قصد دارد:
1. با Plato ID خودش از صفحه ثبت‌نام اقدام کند.
2. یک دوست نیز با Plato ID مستقل خودش ثبت‌نام کند.
3. پس از هر دو ارسال موفق، از دستیار گزارش رکوردهای ثبت‌شده را بخواهد.

هنگام درخواست گزارش، بررسی باید مستقیماً روی دیتابیس اصلی انجام شود و حداقل این موارد را برگرداند:
- تعداد کل درخواست‌ها؛
- Plato ID ثبت‌شده؛
- زمان دقیق `created_at`؛
- وضعیت پذیرش قوانین؛
- تشخیص رکوردهای جدید نسبت به خط مبنای صفر.

**محدودیت:** جدول فعلی ستون وضعیت تأیید مدیریت ندارد؛ بنابراین از همین جدول می‌توان ثبت درخواست و زمان آن را اثبات کرد، اما تأیید/رد مدیریت را نمی‌توان از این ستون‌ها نتیجه گرفت.
